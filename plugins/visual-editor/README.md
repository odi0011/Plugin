# 可视化编辑器（visual-editor）

给核心内容编辑器（文章 / 产品 / 页面 / 自定义内容）追加一颗独立的
「可视化」入口：点开后整页渐隐出蒙版与加载动画，进入全屏拖拽编辑台。
页面不是一段 HTML，而是「区块 → 栏 → 控件」的结构化文档；样式是受
白名单约束的键值对，由服务端编译成作用域 CSS。

插件**没有自己的菜单、列表页、前台接管，也没有任何数据表**。
核心的「代码」「富文本」两个标签一个像素都不改——「可视化」是排在
「AI 编辑」之后的一颗单独按钮，核心渲染的那个模式 radio 仍留在表单里
（保持 `name="content_mode"` 语义），只是视觉上让位给这颗按钮。

## 存储分两处（1.2.0）

| 存的东西 | 存在哪 | 为什么 |
|---|---|---|
| 渲染产物（HTML + 作用域 CSS） | 核心内容字段 | 停用 / 卸载后页面照常渲染 |
| 编辑树、首次接管前的原文备份 | `storage/visual-editor/<源键>.json` | 不污染用户的内容 |

字段里的形态就这么点东西：

```html
<!-- ve:managed -->
<div class="ve-doc ve-doc-page-12">…</div>
<style data-ve-css>…</style>
<!-- /ve:managed -->
```

1.1.0 那种把整棵树 JSON 塞进字段的做法已经取消：字段里不再有插件私有数据，
剥掉两个 HTML 注释后就是普通 HTML 加一段 CSS，基础排布样式内嵌在那段 CSS 里，
不依赖插件的任何资产。旧内容里的内联树在首次打开时自动迁移进插件存储。

两条承诺因此是结构性的，而不是靠自觉：

- **插件停用或卸载后，内容不受影响。** 卸载脚本清 1.0.0 的两张遗留表、
  设置项与 `storage/visual-editor` 目录，**不碰任何内容字段**。
- **原文随时可取回。** 首次接管前的字段内容整段留档，编辑台顶栏的
  「还原原文」把它写回字段（仍需你提交表单才生效）。
- **修订、排期、审批、审计全部免费继承核心。** 写回走核心 `ContentWorkflow`，
  与你在内容表单里按「保存」入库的路径是同一条。

## 使用

1. 打开任意内容表单，点模式条上「AI 编辑」之后那颗「可视化」按钮；
2. 蒙版里的加载动画期间，插件把当前内容解析成编辑树——**首次会慢**，
   动画里的文案会说明原因，转换结果落进插件存储，之后打开就很快；
3. 在全屏编辑台里拖控件、按断点调样式，点顶栏的「保存」——树落存进插件存储，
   服务端渲染出 HTML 与作用域 CSS 并**就地写进内容字段**，走核心
   `ContentWorkflow`：行锁、乐观版本、前后快照、修订与审计一条不少。
   保存后**留在编辑台里**，不跳页；发布状态一律不变（草稿仍是草稿，
   已发布仍是已发布）。

顶栏的「保存」不改发布状态。要发布 / 转草稿仍然回内容表单点核心那两颗按钮——
状态迁移是核心的事，可视化编辑器不越权。

> 保存为什么不走表单提交（1.3.2）：1.3.0 用 fetch 把整张表单发上去，被前置
> 安全层挡成 Forbidden；1.3.1 改回原生 `requestSubmit(核心提交按钮)`，请求形状
> 与手点「发布」逐字节一致，**照样** Forbidden——被挡的不是形状，是请求体里
> 那段编译好的 `<style data-ve-css>` 与整片 HTML。产物本来就由服务端渲染，
> 1.3.2 索性不让它经过浏览器：只上传一棵 base64 的 JSON 树
> （`POST /admin/visual-editor/persist`），HTML/CSS 在服务端生成、在服务端入库。
> 校验一点没少——解码后照样 `normalize()`。

顶栏只留「保存」与「关闭」两颗按钮。另外三个动作不是日常操作，收进「⋯」菜单，
每条带一句说明：「仅写回字段」只把渲染产物写进内容框而不入库（想先回表单看看
再决定时用），「重新导入」按内容字段的当前样子重新解析（在代码模式里改过之后
用），「还原原文」取回首次接管前的原始内容。

## 右侧检查器的控件（1.3.3）

参照 Elementor 的做法，参数不再一律是下拉框与文本框：

- **枚举值**（对齐、主轴 / 交叉轴对齐、显示方式、背景位置、边框线型、按钮
  变体与尺寸等）摆成分段按钮；有语义图标的（各种对齐、背景位置、显示方式）
  直接显示图标，样式项可以再点一次取消设置，回到继承值；
- **长度值**（内外边距、间距、字号、字距、圆角、边框宽度、最小高度、最大宽度）
  是「数字 + 单位 + 滑块」，滑块范围按属性各自给定；
- **内外边距**收成一个盒子：四（或两）个边摆一行、共用一个单位下拉框，
  还有一颗联动开关——开着时改一个边，其余边跟着走；
- **图片类字段**（图片控件的地址、背景图）带缩略图预览与「选择图片」按钮，
  点了直接唤起系统媒体库（`window.MediaPicker`）；坚持手填地址也照旧可以，
  URL 输入框一直在。

## 拖动与右键（1.3.x）

区块与控件在画布里都能直接拖：控件可以在栏内换位、也可以拖到别的栏，
区块可以整体换序，落点由一条蓝色插入线实时指示（按鼠标处于目标上半 /
下半决定插在前面还是后面）。左侧控件轨的拖出仍然是「新建」。

右键任意区块 / 栏 / 控件出菜单（右键本身就完成选中）：编辑、样式设置、
上移 / 下移、复制一份、拷贝、粘贴、粘贴样式、清空样式、删除。
键盘同样认 `Ctrl+C` / `Ctrl+V` / `Ctrl+D` / `Del`（焦点在输入框里时让位给输入框）。
剪贴板只在本次会话内有效，不落存储、不跨标签页。

**导入**的规则是「不丢内容优先」，1.4.0 起把这条规则做到了字节级：
先问一句「转成控件会不会丢东西」——节点树上只要出现 class / id / style /
`data-*` 这类属性，或者 `<style>` / `<script>` / `<svg>` / 表单元素，
就**不转**，整块原样落进自定义 HTML 控件（新的 `raw_html` 字段类型，
服务端一个字节都不改写，只删 NUL 一类控制字符）；只有干净到「转过去
不丢任何东西」的标记才映射成控件（标题 / 段落 / 图片 / 列表 / 引用 /
分隔线 / 可识别的视频 iframe）。1.4.0 之前是先转再消毒，结果 class 与
`<style>` 全被吃掉，一篇带主题样式的页面进来就散成裸文本——保底反而成了破坏。

`<script>` 同样原样留着：这个控件需要 `visual_editor.code`，与代码模式同权限；
前台还有核心 `ContentSanitizer` 按 `updated_by` 是否为启用中的管理员兜底。

没有 `visual_editor.code` 的账号打开一篇已托管内容时，那个原样 HTML 控件
**降级而不是丢弃**：内容过一遍标签白名单后落成富文本控件。排版可能变样，
但一个字不会少——1.4.0 之前这里直接丢弃，只有 `visual_editor.edit` 的人
点一次保存就能把整篇内容清空。

超过区块上限的部分合并成一个 html 控件，绝不静默截断。

**重新导入**以已托管的树为准：字段里已有托管块时沿用原树，只把块外新增的
内容并进来——在代码模式里补了一段再回来导入，不会把原有区块扔掉；
顶栏的「重新导入」则是明确要求按字段当前内容重新解析一次。

## 控件

参考 Elementor Pro 的常用集合，按用途分六组（控件轨里就是这个分组）：

- **基础**：标题、正文、图片、按钮、列表、引用
- **布局**：分隔线、间距、锚点
- **媒体**：图库、轮播、Logo 墙、视频、地图
- **交互**：选项卡、手风琴、翻转框
- **展示**：图标、图标框、图文框、图标列表、提示条、进度条、数字计数、
  星级评分、社交图标、价格表、行动号召、客户评价、时间轴、表格
- **开发**：自定义 HTML（需 `visual_editor.code`）

图库 / 轮播 / Logo 墙 / 选项卡 / 手风琴 / 图标列表 / 社交图标 / 时间轴
用的是「重复字段」：右侧检查器里一行一项，可增删、上下移、复制，行内的
子字段（图片、链接、图标名、富文本）与控件级字段走同一批控件、同一套校验。

**这些控件前台一行 JavaScript 都不需要**，这是硬约束——插件停用后页面必须
照常工作，而插件不给前台注入任何资产。所以：选项卡是一组同名 radio 加
`:checked ~` 兄弟选择器，手风琴是原生 `<details name>`（互斥交给浏览器），
轮播是 CSS `scroll-snap`（可滑动、按张吸附，不自动播放），翻转框是
`:hover` / `:focus-within` + `transform`，数字计数直接显示最终值而不是
滚动动画。地图与视频一样只接受「地点关键词」，`iframe` 地址由服务端拼。

区块预设提供一栏 / 两栏 / 三栏 / 四栏 / 左右侧栏五种列宽组合；平板与手机
默认整宽，多栏在小屏上并排几乎总是错的排布。

## 为什么样式安全

- 样式只能是 `VisualEditorSchema::styleProperties()` 白名单里的属性，
  值必须过对应类型校验（长度 / 颜色 / 枚举 / 比例 / 图片），编译器生成
  选择器，用户碰不到 CSS 文本本身；
- 富文本与自定义 HTML 走 `VisualEditorValue::sanitizeHtml()` 标签白名单，
  `script` / `style` / `iframe` / `form` 整棵删除，事件属性与伪协议链接剥掉；
- 视频只接受「服务商 + 视频 ID」，iframe 地址由服务端拼。

最坏情况下文档 JSON 被写坏，结果是元素不渲染，而不是给访客注入脚本。

**客户端说了不算。** 编辑台里的画布渲染与 CSS 编译是 PHP 侧那两个类的
JS 镜像，只服务预览；点「保存」或「仅写回字段」时客户端只上传树，
`POST /admin/visual-editor/save` 先 `normalize()` 收拾整棵树（未知控件丢弃、
字段逐个过校验、无 `visual_editor.code` 时连 html 控件一起丢），
再由服务端的 `Renderer` / `StyleCompiler` 重新渲染。绕过界面直接构造请求，
进字段的也只有白名单允许的标签与声明。

## 三面对等与一处刻意的例外（只读 API）

`plugin.json` 的 `api` 段一条声明同时派生三面：`/api/v1/ext/visual-editor/<端点>`
路由、`ApiDoc` 契约、`AiAgentActionRegistry` 里的 Agent 动作。执行器统一在
`VisualEditorApi`，HTTP 与 Agent 网关共用核心的扩展控制器，参数白名单、
scope 校验、权限求交只发生一次。

**例外：公开 API 刻意只读**，且恰好两个端点：

| 端点 | 方法 | 用途 |
|---|---|---|
| `visual-content` | GET | 列出正在被可视化托管的内容条目 |
| `document-state` | GET | 一个条目的托管摘要（是否托管 / 是否失配 / 规模计数） |

理由写在 `src/Api.php` 顶部：写入路径只剩一条——后台内容表单提交本身。
扩展 API 的参数是标量且响应字符串有界（4KB 截断），整棵树塞进去只会被
静默截断；与其开一个注定残废的写接口绕开核心工作流，不如让所有落库都
带着核心的校验、修订与审计。这个例外由
`scripts/test_visual_editor_plugin_contract.php` 盯住：端点集合、只读性、
执行器签名都是契约断言。

编辑器要回传整棵树，超出上述边界，因此走后台自己的会话端点
（管理员 + CSRF + 权限三道检查）：

| 端点 | 用途 |
|---|---|
| `POST /admin/visual-editor/convert` | 取编辑树（首次会解析并落存） |
| `POST /admin/visual-editor/save` | 落存树，返回服务端重新渲染的产物（不动内容字段） |
| `POST /admin/visual-editor/persist` | 落存树，并把产物写进内容字段（走核心 `ContentWorkflow`） |
| `POST /admin/visual-editor/restore` | 取回首次接管前的原文 |

只有 `persist` 写内容字段，且写入完全在核心工作流里：`page.edit` / `article.edit`
/ `product.edit` / `content.edit` 必须有，改非草稿内容还要对应的 `*.publish`——
与核心内容控制器同一条规矩，这条路不是绕过核心权限的后门。状态字段一律不碰。
版本冲突（409）如实回报「已被其他会话更新」，不静默覆盖。

## 权限

| 权限点 | 用途 |
|---|---|
| `visual_editor.view` | 只读端点（API 与 Agent） |
| `visual_editor.edit` | 打开编辑台、转换、保存 |
| `visual_editor.code` | 新增或修改自定义 HTML 控件 |

「可视化」模式固定 `persist_as: code`——编译产物含作用域 `<style>`，
只有能用代码模式的账号存得下，这与核心对代码模式的权限约束完全一致。

## 设置

断点（平板 / 手机）与容器最大宽度可在插件设置里调整；渲染时逐值钳制，
坏值最多回到默认布局，不会编译出无效 CSS。

## 卸载

卸载会 DROP 两张 1.0.0 遗留表（`plugin_visual_documents`、
`plugin_visual_revisions`）、清掉设置项，并删除 `storage/visual-editor`
目录（编辑树与原文备份）；**内容字段一律不动**，已托管的内容作为普通 HTML
继续展示。原文备份也一并删除：卸载前随时可以「还原原文」，卸载之后留着
一份内容副本在磁盘上反而是意料之外的残留。只想停用请用「停用」，那不会碰数据。

## 动画与无障碍

蒙版的渐隐渐现、打字机文案、Notch 断点滑块与编辑台入场都走站点自带的
GSAP（`window.gsap`）。拿不到 GSAP 时全部退化成瞬时状态变化而不是报错；
`prefers-reduced-motion: reduce` 下同样降级，CSS 里有对应的兜底类。
