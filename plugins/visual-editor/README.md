# 可视化编辑器（visual-editor）

给核心内容编辑器（文章 / 产品 / 页面 / 自定义内容）追加第三种模式：
富文本、代码之外的可视化拖拽搭建。页面不是一段 HTML，而是
「区块 → 栏 → 控件」的结构化文档；样式是受白名单约束的键值对，
由服务端编译成作用域 CSS。

1.1.0 起插件**没有自己的菜单、列表页、前台接管，也没有任何数据表**。
它只做一件事：在核心内容表单的模式切换条上多加一个「可视化」按钮。

## 自包含 HTML：文档就住在内容字段里

保存时，编辑器把「结构 HTML + 作用域 CSS + 编辑树 JSON」包成一块写进
核心内容字段：

```html
<!-- ve:managed -->
<div class="ve-doc ve-doc-page-12">…</div>
<style data-ve-css>…</style>
<script type="application/json" data-ve-tree="page-12">{…}</script>
<!-- /ve:managed -->
```

这个形态直接兑现两条承诺：

- **插件停用或卸载后，内容不受影响。** 字段里就是普通 HTML 加一段 CSS
  加一段不执行的 JSON；剥掉三个 ve 标记后前台照常渲染，基础排布样式
  就内嵌在那段 CSS 里，不依赖插件的任何资产。卸载脚本只清理 1.0.0 的
  两张遗留表和设置项，**不碰任何内容字段**——只想停用请用「停用」。
- **修订、排期、审批、审计全部免费继承核心。** 写回走的是原表单提交，
  随核心 ContentWorkflow 入库；可视化改动天然出现在核心的修订历史里。

树 JSON 跟着内容走，所以再次打开就能继续可视化编辑，不需要反查任何表。

## 使用

1. 打开任意内容表单（文章 / 产品 / 页面 / 自定义内容），切换条上点「可视化」；
2. 字段里还没有托管块时，点「导入当前内容」把已有 HTML 变成文档；
3. 拖拽控件、改样式（三个断点独立设置）、保存——和其他模式一样走同一个表单。

**导入**的规则是「不丢内容优先」：认识的标记映射成对应控件（标题 / 段落 /
图片 / 列表 / 引用 / 分隔线 / 可识别的视频 iframe）；只有内联内容的 div
整体转成富文本控件；其余整块**原样**落进自定义 HTML 兜底控件，不改一个字节。
超过区块上限的部分合并成一个 html 控件，绝不静默截断。

**重新导入**以已托管的树为准：字段里已有托管块时沿用原树，只把块外新增的
内容并进来——在代码模式里补了一段再回来导入，不会把原有区块扔掉；
就算树脚本被人为改坏，块内的结构 HTML 也会按标记还原成区块。

## 为什么样式安全

- 样式只能是 `VisualEditorSchema::styleProperties()` 白名单里的属性，
  值必须过对应类型校验（长度 / 颜色 / 枚举 / 比例 / 图片），编译器生成
  选择器，用户碰不到 CSS 文本本身；
- 富文本与自定义 HTML 走 `VisualEditorValue::sanitizeHtml()` 标签白名单，
  `script` / `style` / `iframe` / `form` 整棵删除，事件属性与伪协议链接剥掉；
- 视频只接受「服务商 + 视频 ID」，iframe 地址由服务端拼。

最坏情况下文档 JSON 被写坏，结果是元素不渲染，而不是给访客注入脚本。

## 三面对等与一处刻意的例外（只读 API）

`plugin.json` 的 `api` 段一条声明同时派生三面：`/api/v1/ext/visual-editor/<端点>`
路由、`ApiDoc` 契约、`AiAgentActionRegistry` 里的 Agent 动作。执行器统一在
`VisualEditorApi`，HTTP 与 Agent 网关共用核心的扩展控制器，参数白名单、
scope 校验、权限求交只发生一次。

**例外：1.1.0 的公开 API 刻意只读**，且恰好两个端点：

| 端点 | 方法 | 用途 |
|---|---|---|
| `visual-content` | GET | 列出正在被可视化托管的内容条目 |
| `document-state` | GET | 一个条目的托管摘要（是否托管 / 是否失配 / 规模计数） |

理由写在 `src/Api.php` 顶部：写入路径只剩一条——后台内容表单提交本身。
扩展 API 的参数是标量且响应字符串有界（4KB 截断），整棵树塞进去只会被
静默截断；与其开一个注定残废的写接口绕开核心工作流，不如让所有落库都
带着核心的校验、修订与审计。这个例外由
`scripts/test_visual_editor_plugin_contract.php` 盯住：端点集合、只读性、
执行器签名都是契约断言。

编辑器的「导入」要回传整棵树，超出上述边界，因此走后台自己的会话端点
`POST /admin/visual-editor/convert`（管理员 + CSRF + `visual_editor.edit`
三道检查，只读返回，不落库）。

## 权限

| 权限点 | 用途 |
|---|---|
| `visual_editor.view` | 只读端点（API 与 Agent） |
| `visual_editor.edit` | 打开面板、导入、保存 |
| `visual_editor.code` | 新增或修改自定义 HTML 控件 |

「可视化」模式固定 `persist_as: code`——编译产物含作用域 `<style>`，
只有能用代码模式的账号存得下，这与核心对代码模式的权限约束完全一致。

## 设置

断点（平板 / 手机）与容器最大宽度可在插件设置里调整；渲染时逐值钳制，
坏值最多回到默认布局，不会编译出无效 CSS。

## 卸载

卸载会 DROP 两张 1.0.0 遗留表（`plugin_visual_documents`、
`plugin_visual_revisions`）并清掉设置项；**内容字段一律不动**，
已托管的内容作为普通 HTML 继续展示。只想停用请用「停用」，那不会碰数据。
