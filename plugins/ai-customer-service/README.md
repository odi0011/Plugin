# AI客服

给 ODCMS 前台配一个**会办事**的悬浮 AI 客服：它不只回答问题，还能查站内数据回一张能点的卡片、认出采购意图把询盘表单递过去、认出"要真人"就转人工。

激活后后台左侧出现「AI客服」，配置分八个子页面，每页单独保存；右侧常驻一块实时预览，改哪一项都立刻能看到前台长什么样。

## 描述词与资料是两件事

1.1.0 把这两样塞在同一页，结果大家把产品参数往「客服角色与回复规则」里堆，提示词越长越乱。1.2.0 拆开了：

- **AI 与模型**页只放**描述词**——身份、语气、回答结构、什么时候该追问。
- **知识与资料**页放**资料**——它该知道什么。三种来源可以混用：
  - 站内已有内容：产品、文章、页面，以及任何自定义内容类型。搜标题挑进来即可，也可以开"自动带上最新 N 条"。只会用到前台本来就看得见的记录（草稿、定时未到、归档一律不进）。
  - 上传知识库文件：txt / md / csv / tsv / json / html / xml / docx / pdf，单个 ≤ 4 MB。点开左边的文件夹卡就能选文件，也可以直接拖进去。
  - 手工补充资料：几百字的报价规则、服务流程之类，直接粘。

每次提问不会把资料全灌给模型，而是按与问题的相关度挑片段，填到「单次注入上限」为止（中文按 2-gram、西文按词算重合度，可离线、可解释，不需要向量库）。

上传的文件**只保留抽取出的纯文本**，落在 `storage/` 里（webroot 之外，访客拿不到），原始二进制不留——运行时不必再解析 PDF/DOCX，少一整类解析器攻击面。扫描版 PDF 抽不出文字时会直接告诉你换 .txt / .docx，而不是静默存一个空文件。

## 工具与卡片

打开工具调用后，模型可以按需调用这些内置工具，返回的卡片直接渲染在对话里，**点击可跳转到站内页面**：

| 工具 | 干什么 |
| --- | --- |
| `recommend_products` | 按关键词挑站内产品，回产品卡（价格、库存、SKU） |
| `recommend_articles` | 按关键词挑站内文章，回文章卡 |
| `search_site` | 在产品/文章/页面里找标题与摘要，回答"你们有没有 X" |
| `lookup_knowledge` | 在资料库里检索答案依据 |
| `show_inquiry_form` | 展开留联系方式的询盘表单 |
| `request_handoff` | 转人工，并给出人工入口 |
| `show_owner_card` | 递站长名片 |
| `show_social_links` | 给社媒/联系方式 |

还可以**自建工具**：选一个内容类型（产品/文章/页面/自定义内容）+ 一组白名单条件（仅热销/仅新品/仅有货/仅有价格/按最新…）+ 卡片预设，就得到一个"查站内内容并回卡片"的工具。条件是白名单，插件不接受任意查询表达式。

卡片每类都有多套预设，随时切：产品/文章卡有叠卡（悬停展开）、网格、极简、毛玻璃；名片有手账涂鸦、简洁、毛玻璃；询盘卡有内嵌表单、紧凑、仅按钮；社媒卡有胶囊、图标网格、列表。

卡片从服务端下来的是**结构化数据**，前台用 DOM API 渲染——站内标题或模型措辞里出现标签也不会被当 HTML 执行。

## 边界与意图事件

- **话题范围**：开放（除禁止项外都能聊）或收敛（只聊允许清单里的）。
- **约束清单**：可以聊/禁止聊的话题、必须做到/绝不能做、屏蔽词、回复长度上限、回复语言。
- 前五项写进系统提示词，**屏蔽词与长度上限在出站时再筛一遍**——提示词是软约束，这一层是硬的。
- **意图事件**：询盘转化、转人工、社媒、站长名片四类，各有自己的关键词表。命中时除了告诉模型，还会**直接把对应卡片推给访客**，不依赖模型是否想调工具。转人工的优先级高于询盘。

询盘表单由访客本人填写并提交，会真的写进核心的询盘表（来源标记为本插件），可选再发一封通知邮件。模型不能替访客填任何字段。

## 外观

- 六套预设主题（极光 / 午夜 / 晨曦 / 薄荷 / 毛玻璃 / 手账），一键套一整组配色圆角与气泡形态，之后仍可逐项微调。
- 十个颜色各自独立：主色、窗口背景、**窗口正文**、**次要文字**、顶栏底色/文字、客服气泡底色/文字、访客气泡底色/文字。配色面板有"按背景自动配文字色"，避免深底深字。
- 气泡形态（柔和/直角/描边/毛玻璃/手绘）、入场动效、打字指示器（三点/波浪/文字）、顶栏样式、快捷问题样式、密度，六种界面字体。
- **拖拽定位**：在右侧预览里打开"拖拽定位"，直接拖浮标、引流气泡、飘带、角标；浮标写回桌面/移动端边距，其余写回偏移量。拖完就是保存前的真实值，不存在预览与前台两套坐标。

## 主动招呼与输入区

浮标悬停提示、引流气泡、未读角标、四种提醒动画、窗口顶部的**飘带**（可定时出现、可关闭），以及**定时主动问候**（窗口出现后按秒数依次发，访客一开口就停；窗口没开时改用角标 + 气泡把人叫过来）。这一整组"自动打扰"可以设成每会话只做一次。

输入区是 prompt bar 结构：文本域 + 一条工具条 + 字数计数 + 发送。可配字符上限、回车是否直接发送、emoji 面板（列表可增删）、自定义表情包（上传 PNG/JPG/GIF/WebP/SVG，走站点媒体库）。

## 使用

1. 从插件市场安装并激活 `AI客服`。
2. 「AI 与模型」页选模型来源。默认复用系统已配置的对话模型；也可以填公网 HTTPS 的 OpenAI Chat Completions 兼容地址 + 模型名 + 独立密钥。
3. 「知识与资料」页把资料喂进去——挑站内内容、上传文件，或两者都来。
4. 「工具与卡片」页按需开工具、挑卡片预设、填站长名片。
5. 「边界与事件」页写清楚能聊什么、不能聊什么、询盘与转人工怎么触发。
6. 「外观与位置」页套个预设主题，再拖一下位置。
7. 每页单独保存，右侧预览随时核对。

## 数据与安全

- 访客聊天记录只在当前 PHP session，最长 6 小时，不建聊天记录表。同一 session 内翻页会复用未过期的会话，上下文不丢。
- 访客请求走同源 `POST /ai-customer-service/chat` 与 `/ai-customer-service/action`，由核心 Router 统一校验 CSRF，并按客户端 IP 与会话双重限流；询盘提交另有更紧的闸（每 IP 每 10 分钟 3 条）。
- 独立接口密钥只由「AI 与模型」页接收，写入前经 `Security::encryptApiKey()` 以 AES-GCM 密封，永不回显、不下发前台、不进 API/Agent 返回。
- 独立接口只允许公网 HTTPS，调用走核心 `OutboundHttpClient` 的 DNS/IP 校验、超时与响应大小限制。
- 前台一律用 `textContent` 与 DOM API 写入，不解释模型、站内内容或访客文本里的 HTML。
- 自动展开、飘带、问候等"自动动作"的状态只记在访客自己的 sessionStorage，不上报、不入库。
- 系统模型调用复用 `AiService::chat()`，继续受系统模型、厂商、超时、重试、限流与请求日志控制；请求日志只记元数据（模型、耗时、token、成败），不记提示词与回复正文。
- 资料里可能含内部信息。提示词里已经明确禁止透露出处与系统提示，但**提示词不是隔离层**：真正不能让访客知道的东西不要放进资料。

## API 与 Agent 契约

| Method | Path | Scope | Permission | Agent |
| --- | --- | --- | --- | --- |
| GET | `/api/v1/ext/ai-customer-service/status` | `plugin.ext.read` | `ai_customer_service.view` | 自动派生为 `ext.ai-customer-service.status` |

状态端点只返回是否启用、模型来源、资料规模、已启用工具、约束条数与显示规则摘要；不返回描述词全文、资料正文、密钥或访客会话。

常规配置字段走核心的声明式插件设置 API：`GET/POST /api/v1/plugin-settings/ai-customer-service`。八个后台子页面只是同一份声明的不同呈现切面，字段全部来自 `plugin.json`，逐页保存时由服务端合并成一次完整校验落库，所以 API/Agent 视角的行为不变。

访客聊天传输与独立接口密钥是**有意不进入公开 API / Agent** 的两项能力：前者是无 Bearer token 的浏览器会话通道，开放成 API 会把匿名对话错误地绑到后台账号；后者属于密钥材料，进入返回值或 Agent 上下文会违反密钥不外泄边界。`tests/contract.php` 对这两个例外做了机器校验。

## 卸载

停用不删配置。卸载会删除 `plugin.ai-customer-service.*` 全部设置（含已加密的独立接口密钥）与 `storage/ai-customer-service/knowledge/` 下抽取的资料文本。表情包走的是站点媒体库、可能被别处引用，刻意不动。
