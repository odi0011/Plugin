# AI客服

给前台站点装一个**会办事**的悬浮 AI 客服：不只是回答，还能查站内内容、回一张能点的卡片、
在识别到采购意图时把询盘表单拉出来、要转人工就转人工。

- 版本以 `plugin.json` 为唯一真源（PHP 常量、前台 JS、五个 `assets[].version` 都跟着它走）
- 需要核心 `7i` / PHP 8.0+ · MIT
- 后台入口：左侧菜单「AI客服」，权限 `ai_customer_service.manage`

## 八个配置子页面

| 页面 | 管什么 |
| --- | --- |
| 会话内容 | 身份、欢迎语、快捷问题、人工转接入口、上下文长度与提问频率、聊天前的同意确认 |
| 显示与触发 | 设备/页面/延迟/滚动/离开意图、提醒动画与角标、引流气泡、飘带、定时主动问候、服务时段（含时段外的说明条）、体验增强（时间戳/接续会话/未读提醒/浮标多渠道）、按国家与语言显示 |
| 外观与位置 | 六套预设主题、七个可独立调的形态轴（气泡 / 动效 / 密度 / 顶栏 / 快捷问题 / 边缘 / 字面）、界面字体、十个可调颜色、桌面/移动边距（右侧预览可直接拖） |
| AI 与模型 | 模型来源（系统模型或独立 OpenAI 兼容接口）、**描述词**、生成参数 |
| 知识与资料 | **资料**来源：站内产品/文章/页面/自定义内容 + 上传的知识库文件 + 手工补充；注入额度与挑选策略 |
| 工具与卡片 | 八个内置**工具**开关、自定义工具、五类**卡片**预设、站长名片资料 |
| 边界与事件 | 话题范围、允许/禁止清单、屏蔽词、越界回复；询盘/转人工/社媒/名片四类意图识别 |
| 输入与表情 | 字符上限、回车行为、emoji 面板、自定义**表情**包 |

逐页保存：每页只提交自己名下的字段，其余字段以库中现值回填。回填前会把越界或为空的
数字字段修回合法值——否则在 A 页清空一个 `min > 0` 的数字框，B/C/D 页会一直报
「有 N 个设置项校验失败」，而且提示里既没有字段名、出错字段也不在当前页上。

## 描述词与资料是两件事

这一版刻意把它们拆开：

- **描述词**（AI 与模型页）只写身份、语气、回答结构与流程。它进系统提示词的固定段。
- **资料**（知识与资料页）是客服能引用的事实。每次提问按与问题的相关度挑片段，直到用满
  「单次注入资料上限」。中文按 2-gram、西文按词做重合度打分——不引向量库，完全可离线、
  可解释，对"哪个型号防水""怎么退货"这类具体问句够用。

站内内容只会取**前台本来就看得见**的记录（走核心 `ContentWorkflow::applyPublicScope`），
草稿、定时未到、已归档一律不进上下文。

上传的知识库文件只保留**抽取后的纯文本**，落在 `STORAGE_PATH` 下（webroot 之外，访客
下载不到），原始二进制不留：运行时不需要再解析 PDF/DOCX，少一整类解析器攻击面，卸载时
删目录即可，也不用建表。支持 txt / md / csv / tsv / json / html / xml / docx / pdf；
PDF 是尽力而为（扫描件抽不出文字时会明确告诉你改用别的格式，而不是静默存一堆乱码）。

## 工具与卡片

内置八个工具：推荐产品、推荐文章、站内检索、查资料库、拉起询盘表单、转人工、递站长名片、
给社媒方式。走 OpenAI function calling（系统模型经 `AiService::chat` 的 `tools`，独立接口
直接发 `tools`），一次提问最多 1~3 轮。

自定义工具是**声明式**的：选内容类型 + 勾白名单条件（仅推荐位/仅热销/仅新品/仅有货/
仅有价格/按最新排序）+ 返回条数 + 卡片预设。不接受任意查询，也不执行任何代码。

两条硬规则：

1. **工具只读。** 没有任何工具会写库、发信或改配置。询盘写入走访客自己提交的表单端点，
   不是模型直接调用——否则模型幻觉出来的联系人就会变成真数据。
2. **卡片回给浏览器的是结构化数据，不是 HTML 片段。** 前台用 DOM API 渲染，所以模型措辞
   或站内标题里就算带标签也不可能变成可执行内容。

卡片预设里，产品叠卡、站长涂鸦名片、后台资料柜的文件夹卡是**按站长提供的设计稿原样照搬**
的（`assets/preset-cards.css` 与 `admin.css` 内注明来源），只加了 `acs-` 前缀防冲突、
给绝对定位补了舞台容器、用 `transform: scale()` 缩进面板宽度。声明值没有改动，契约测试
会盯住几个签名值防止后人当魔法数字优化掉。

## 边界

两道：写进系统提示词（软约束，体验最好），出站再筛一遍（屏蔽词与长度上限必须服务端硬兜）。
意图识别用关键词而不是再调一次模型——转人工/询盘这类动作要求可预测、零延迟、站长能自己
改词表，交给模型只会引入一次额外调用和一类新的幻觉。

## 预设是形态，不是配色

六套预设（素白 / 墨黑 / 午夜 / 薄荷 / 陶土 / 手账）的验收标准是可证伪的：**任意两套至少在
三个非颜色维度上不同，其中至少一个在闭合态就能看出来** —— 挂件九成时间只露那颗浮标，
差异只体现在展开后的聊天区，等于换预设什么都没换。落点分别是：

| 维度 | 落在哪 |
| --- | --- |
| 闭合态 | 浮标形态（圆 / 胶囊）、图标、胶囊圆角、直径 |
| 轮廓 | `panel_radius` 一个值推出五级圆角阶梯，带动全窗 27 处圆角，不只是面板那一个角 |
| 边缘 | `theme.edge` 六档：描边 / 全平 / 玻璃 / 发光 / 硬偏移 / 内斜面 |
| 排版 | `theme.type` 三档：字重 + 字距 + 行高。**不动字族** —— 中文站上 Inter、Quicksand 这类基本都没装，字族差异会全塌成同一种 |
| 密度 | `theme.density` 三档，驱动面板 / 轮次 / 行内 / 气泡 / 顶栏 / 聊天区顶部一整组间距变量 |
| 顶栏 | `theme.header_style` 四档：纯色 / 浅底 / 主色 / 极简（极简那档整条横栏都没有） |
| 签名 | 五套各有一条独占规则（墨黑拍平胶囊、午夜顶栏一条两端淡出的主色光线、薄荷把卡片列表变成表格行、陶土给气泡一道内压痕、手账铺纸的横线）。素白故意没有：它的定位就是不抢站点风格 |

七个轴都是站长可以**脱离预设单独调**的，预设只是替他各选了一组。投影是例外：六套一律
`none`，那是站长自己的开关，预设不该替他按下去；海拔差异走 `theme.edge`，两者可以叠加。

`theme.edge` 与 `theme.type` 都寄生在 `theme_json` 这个已有的 textarea 里，没有新增声明
字段 —— 核心的字段上限是 100，这个插件已经用到 96。

## 前台

对话区按 [beautifului.dev](https://www.beautifului.dev/) 的形态做：一轮回复是一个 turn
容器（工具 chip → 正文 → 卡片共用一条基线），工具调用是带状态点的横向 chip，输入区是
Prompt Bar，产品卡是行式 Recommendation Card。配色全部来自后台字段，所以同一套形态在
浅色与深色站点都成立。

- 访客通道：同源 `POST /ai-customer-service/chat` 与 `/ai-customer-service/action`，
  CSRF 由核心 Router 统一校验。
- 握手通道：`GET /ai-customer-service/session`（`no-store`）。整页缓存会把渲染那一刻的
  CSRF token 与会话 id 冻进 HTML 发给所有访客，于是第一句话就撞 419（核心发的是**纯文本**，
  不是 JSON）或 422 `conversation_expired`；两者都不是"刷新一下"能修的，刷回来的还是同一份
  缓存。前台五处 POST 统一走一个 `postForm()`：认出这两种失败就用握手端点换一份属于自己的
  token 与会话 id，把原请求重放一次——**只重放一次**，握手也失败就照实说。
- 会话只存在 PHP session 里（同一 session 复用未过期会话，翻页不丢上下文），不建聊天记录表。
- 等待上限由服务端算好下发（`timeoutMs`，30–180 秒）。开着工具调用时服务端最坏要跑
  `(工具轮次 + 1) × 30` 秒，浏览器这边写死 25 秒就会先弹"超时"、服务端随后照样答完并写进
  会话——下次刷新历史里凭空多出一问一答，而访客早已把同一句又发了一遍。超时的那条因此
  标成中性的「等待确认」（不是红色的"未发送"，也不把原文塞回输入框），随后自动拉一次
  `action=history`：末尾那一问确实就是刚超时的这句，就把答案补进对话。
- 限流：每 IP 每分钟按配置、每会话每分钟 `min(20, max(2, 配置))`、询盘提交每 IP 每 10 分钟 3 条。

## 体验增强

「显示与触发」页最后一张卡（五个开关，只写 `experience_json` 一个字段；默认只开「刷新后接续会话」）：

- **显示消息时间** — 气泡下方一行 `HH:MM`，时间戳由服务端给。
- **刷新后接续会话** — 上下文本来就一直在 PHP session 里（每轮对话都要用），之前只是没回传
  给浏览器，访客一刷新就看到空窗口、以为客服把话忘了。开启后**首次展开面板**才异步拉一次
  （`action=history`），关着的挂件不产生任何请求。卡片刻意不存档：那是查询结果的快照，存进
  session 会让并发会话的体积失控，回放时也可能已经过期。
- **新回复提示音 / 标签页未读提醒** — 提示音用 WebAudio 现场合成一声「叮」，不为此多下一个音频
  文件；角标与标题计数只在面板收起或页面切到后台时才动，回到前台立即还原。
- **上报转化事件** — 有 `gtag` 就发 GA4 事件，有 `dataLayer` 就 push；两个都没有就什么都不做，
  埋点异常被吞掉，绝不影响会话。事件名：`acs_open` / `acs_message_sent` / `acs_intent_*` /
  `acs_channel_click` 等。

同一张卡里还有 **浮标多渠道展开**（Chaty 的形态）：浮标旁多一个小按钮，点开摊出微信/电话/
邮箱/WhatsApp 等入口，可选圆形图标竖排或带文字的卡片，最多显示 12 个（社媒列表本身也就收 12 条）。
数据源直接复用「工具与卡片」页的**站长名片**社媒列表，不做第二份编辑器——两处各填一遍必然会不一致。
点击可复制的项会真读一次剪贴板结果，失败就提示手动复制，不假报成功。

渠道共 19 种：微信、WhatsApp、Telegram、Messenger、LINE、Viber、短信、Skype、Discord、
Facebook、Instagram、LinkedIn、X、YouTube、TikTok、GitHub、邮箱、电话、网站。号码类渠道
（微信/电话/Viber/短信）按纯文本收，拼 `href` 时再转成 `tel:` / `sms:` / `viber://chat?number=`，
微信号则是点击复制。每个渠道还能单独挂**一张二维码图**：桌面端鼠标悬停、键盘 focus 或点一下
在旁边展开；触屏上链接类渠道点了直接跳（不弹图），只有复制类（微信）会把图钉住——手机上
长按识别图中二维码是常规操作，遮住它反而少一条路。浮层跟着触发元素定位，聊天区一滚就收掉，
免得停在跟它无关的消息上面。二维码是站长自己上传的图，插件不调第三方生成接口、也不往前台塞
一个二维码编码器——前者会把访客要访问的地址送出站，后者为了一张图多背几十 KB。

## 按国家与语言显示

「显示与触发」页最后一张卡（写 `targeting_json`）。国家与语言两个维度各自独立，任一条判定
「不显示」浮标就整个不渲染：

- **国家**取自 CDN / 反向代理的地区请求头（`CF-IPCountry`、`CloudFront-Viewer-Country`、
  `X-Country-Code` 等）。插件不自带 IP 库、也不回源任何第三方查询接口。
- **语言**取自浏览器的 `Accept-Language`（按 q 值排序）。填 `zh` 能同时命中 `zh-CN` / `zh-TW`，
  要精确就填 `zh-cn`。
- 名单为空时该维度自动回到「不限制」——`allow` + 空名单会把浮标全站关掉，那看起来像插件坏了
  而不像一条规则。未知国家/语言在 `allow` 下不显示、在 `deny` 下显示：名单式规则的语义就是
  「只对名单内的人开」。
- 这是**展示层的定向，不是访问控制**：请求头可以伪造。聊天接口故意不做地理判定（和页面路径、
  服务时段一致），已经打开的会话不该因为一次 CDN 抖动缺了请求头就中途断掉。
- 开着定向时会在 `frontend.head` 补一条 `Vary`（用到的地区头 + `Accept-Language`）。整页缓存
  不知道页面按请求头变化，就会把第一个访客的那一份发给所有人——规则看着配好了其实随机生效。
  只在真的开了定向时才发：没开的站点不该因为装了这个插件就让整站缓存按语言分片。一个地区头都
  读不到时也仍然声明一条，否则「缺头 → 不显示」这个结果会被缓存住，等 CDN 恢复发头了还在发
  那份没有挂件的页面。
- 面板里会直接写出服务端**这一次后台请求**读到的国家与语言，配完发现浮标不见了，能立刻分清
  是规则生效还是压根没有地区请求头。

## 服务时段与非服务时段

「按服务时段显示」定义营业日与营业时间。两件事值得单说。

**判定在浏览器，不在服务端。** 这一条的结果随时间变，而整页缓存会把渲染那一刻的答案冻住：
上午缓存下来的页面到了晚上还带着挂件，晚上缓存的第二天上午一整天都没有挂件。定向那边靠 `Vary`
解决同类问题，但「时间」没有对应的请求头，`Vary` 救不了。所以规则下发给客户端现算——和「按设备
显示」一样是客户端规则。用的是**站点时区**（下发时区名而不是算好的偏移量：偏移量含夏令时，一旦
被缓存住，过了切换日就会差一小时），因为站长说的「9:00 上班」是他自己的 9:00，不是访客那边的
9:00。只在初始化时判一次：访客正聊着到了下班点把挂件抽走，比状态略旧糟得多。后台面板里会写出
服务端此刻的时区、星期与钟点，配完能当场对一眼。

**时段外可以不消失。** 默认仍是整个挂件不出现（已经在用这个功能的站点，本意就是那段时间别
出现，升级插件不该让挂件突然全天可见）；「体验增强 → 非服务时段」里可以改成「照常出现 + 顶上
一条说明」——原来的行为是访客在那段时间连留个联系方式的地方都没有。AI 仍然照常回答：聊天接口
不看服务时段，否则访客正聊着到了下班点就会被中途掐断。说明条不可关闭，它解释的是「现在这个
状态」，关掉之后访客就再也看不到自己为什么等不到人工回复了。

## 聊天前的同意确认

「会话内容」页最后一张卡（写 `consent_json`，默认关）。开启后访客发第一条消息前要先勾一次
同意：输入框与快捷问题都锁着，勾完点按钮才解锁；标题、正文、按钮文案与一个可选的隐私政策
链接都能改，清空则各自回落到默认文案（否则开着开关又把文字删干净，得到的是一个点不动的空
门槛）。同意记在服务端 session 里，一个会话只问一次，「重新开始」不会把它清掉。

这道门槛在右侧预览里是活的：拨开关、改标题正文按钮当场就能看到，不用先保存再刷新。前台维持
「关了就一个字节都不输出」，预览里才会把关着的节点也画出来交给后台 JS 拨。正文按 600 字上限
排能占掉半个面板，所以给它封了高度、超出自己滚。

服务端也拦一道：`/chat` 与询盘提交在未同意时返回 403 `consent_required`，所以前台被 CDN
缓存成旧版本也绕不过去；反过来，前台拿到这个码会自己把门槛重新升起来，不会卡在一个看起来
能用其实发不出去的输入框上。`action=history` 故意排在门槛之前——它只读服务端已有记录，拦了
只会让刚打开面板的访客先吃一条错误提示。

前台还统一补了：正文里的网址自动变可点链接（用 DOM API 切分文本节点，不拼 HTML）、发送失败
把内容放回输入框并给气泡标「未发送」、请求 25 秒超时、等回复时不再 `disabled` 输入框（会打断
中文输入法候选）、往上翻历史时新消息不把视图拽回底部、Esc 关闭并把焦点还给浮标、
iOS 安全区（`env(safe-area-inset-*)`）边距。

**自动弹出与「访客自己点开」是两条路。** 延时自动弹出既不碰焦点也不圈 Tab：访客可能正在填
站点自己的搜索框或结账表单，几秒后光标被挪进聊天框，后面敲的字就全打到别处去了；把键盘用户
锁在一块他没要求打开的面板里同样是纯粹的伤害。访客自己点开的面板才圈住 Tab（Esc 出得去），
而且这时候才对读屏声明 `aria-modal` —— 圈 Tab 与 `aria-modal` 必须成对，只圈不声明，读屏会
说页面还能去而键盘出不去。


按 AGENTS.md，能力原则上要在「后台页 / API / Agent」三面对等。这个插件有两处**有意不进入公开 API / Agent**：

1. **访客聊天与询盘提交**只走同源 CSRF 会话通道。访客没有后台账号，做成需要 Bearer token
   的 `/api/v1` 端点会把匿名会话错误地绑到某个管理员身上。
2. **独立接口密钥**不进声明式 settings。一旦声明，它就会出现在 `/api/v1/plugin-settings`
   的可读契约与 Agent 上下文里。它只由配置页接收、加密后单独落一个 setting 键，永不回显。

对外只声明一个只读端点 `GET /api/v1/ext/ai-customer-service/status`（派生 Agent 动作
`ext.ai-customer-service.status`，scope `plugin.ext.read`），返回是否启用、模型来源、资料
规模、已启用工具与显示规则摘要——不含描述词全文、资料正文、密钥或访客会话。

## 卸载

删除本插件的全部设置（含加密的独立接口密钥）与上传的知识库文本。表情包走的是核心媒体库
目录、可能被其他内容引用，刻意不动。

## 本地契约测试

```
php plugins/ai-customer-service/tests/contract.php
```

除了声明与边界，它还盯住几类**已经踩过的**回归：面板必须用 flex（grid 定位行会随可选节点
错位把聊天区压塌）、聊天区必须关掉横轴溢出、引流气泡必须显式给宽度（否则塌成一列单字）、
JS/PHP 输出的每个类名都必须有对应 CSS 规则（防"换了 DOM 忘了同步样式"）、照搬的设计稿
签名值不得改动。

1.5.2 添的一组都是"写了但永远不执行"：截断时找换行符必须用双引号 `"\n"`（单引号里那是
反斜杠加字母 n 两个字符，正常回复里不会出现，整条"按段落末尾断句"等于没写）、`mb_strrpos`
的结果不得直接转 int（`false` 会变成 0，与"命中第 0 位"混在一起）、句末标点表必须含英文
`!` 与 `?`；询盘字段清单在既没邮箱也没电话时必须补一个（服务端要求二者至少填一个，清单里
没有那两个框时访客怎么改都提交不上去）；等待上限必须走 `outboundBudgetSeconds()`，独立接口
按 `CUSTOM_TIMEOUT`、系统来源按供应商自己配的 `request_timeout`（都按 30 秒估的话，供应商
默认 60 秒的站点会让浏览器先放弃、服务端照样答完写进会话）。同一轮还把**主题默认值的四方
对齐**钉住：`styleVars()` 里每个变量在 `plugin.json` 的 `default`、`config()` 的 sanitizer
兜底、CSS 的兜底、`admin.js` 的预览映射四处必须相等 —— 不等时的症状是"后台预览与前台不一样"
或"清空一栏之后外观自己变了"，`bot_bubble_color` 就是这么一处（`#F4F4F5` 对 `#F3F4F6`）。
`admin.js` 里每个 `val('x', '#hex')` 的兜底也必须等于声明默认值：自动配色算的是"这一栏为空时
按什么底色判明暗"，兜底错了就写出白底白字这类看不见的结果（顶栏默认是白色，按主色判会配白字）。

1.5.1 添的一组都在盯"看不出来的失败"：**握手路由必须是 GET**（CSRF 只校验 POST 一类，用
POST 去换 token 会被同一道门挡在外面）、握手响应必须 `no-store`、前台**只准有两处 `fetch(`**
（握手的 GET 与 `postForm` 的 POST，多一处就多一条不会重握手的死路）、419 必须单独认
（`response.json()` 会在纯文本上抛，错误文案就变成"网络似乎断开了"）、重放只能一次、
等待上限必须由 `chatTimeoutMs()` 从 `CUSTOM_TIMEOUT` 推出来而不是前台再写一个数字。
无障碍侧钉住：挂件隐藏时必须 `visibility: hidden`（只有 `opacity: 0` 的话整块面板仍在 Tab
序里，读屏也照念）、"正在输入"必须另有 sr-only 文本（那三个点是纯 CSS 动画，读屏一个字都
拿不到）、一次性回填历史前后必须 `aria-live` off→polite 并补一句分隔（不然读屏用户要听完
整段旧对话才能开口）、禁用发送键之前先把焦点挪走。后台侧钉住：`KNOWLEDGE_LIMIT` /
`STICKERS_LIMIT` 必须等于 `plugin.json` 里对应字段的 `max_length`（小了白挡、大了写进去
被核心截断成坏 JSON）、余量必须在 `storeUpload()` **之前**算、目录写失败要把这一批文件
原路撤回（否则那些 `.txt` 在后台既看不见也删不掉）、因为上限少收了几个必须报数
（静默少收只会被当成上传坏了）。

1.5.0 添的一条覆盖面最大：**七个主题轴（气泡形态 / 气泡动效 / 密度 / 顶栏 / 快捷问题 /
边缘 / 字面）必须六处对齐** —— `normalizeTheme()` 的白名单、`defaultTheme()` 的兜底、
`plugin.json` 里 `theme_json` 的声明默认值、CSS 里的档位规则、后台分档控件的选项键、
预设画廊的中文名。少一处都不报错：站长会看到「选了没反应」（缺 CSS）、「像保存失败」
（后台给了白名单外的选项，保存后被静默收回默认档）或者画廊里那一档干脆不显示（缺中文名）。
CSS 侧是**双向**比对，多一条也算失败 —— `.acs-head--gradient` 就是白名单里早就删掉了
`gradient`、CSS 却还留着的死代码。故意不写规则的基准档（`solid` 顶栏就是 `.acs-header`
本身、`none` 动效就是不动）在测试里显式列成 `bare`，好让「缺规则」和「本就不需要规则」
可区分。同一轮还钉住：`TONE_DARK_MAX` 的 PHP 与 JS 两份必须相等（不等时同一套配色会在
后台预览判浅底、前台判深底，投影与描边全错）、`renderWidget()` 的 `static $rendered` 与
前端的 `dataset.acsBound` 两个防重复守卫、以及手机软键盘那三处（`--acs-kb` 的兜底定义 +
抬挂件 + 矮面板）。

1.4.0 又添了几条：开着定向必须声明 `Vary`（否则整页缓存把第一个访客的那份发给所有人）、
浮标渠道竖排必须有高度上限与滚动（12 个渠道配大浮标会顶出屏幕）、同意正文必须封顶、
锁住的输入框必须用 `aria-describedby` 指到同意正文、门槛重新升起时焦点不能落在 disabled
的输入框上、聊天区滚动必须收掉二维码浮层、同意门槛必须接进后台预览。

1.4.3 添了两条同一家族的：**服务时段不得在服务端判**（结果会被整页缓存冻住），以及
**`var(--x)` 引用的自定义属性必须有定义或有 fallback** ——没定义又没 fallback 时整条声明在
计算值阶段失效，页面不报错、样式静默丢掉（写 `--acs-soft` 那次就是这样）。客户端的时段判定
另有 1092 组真值表跟服务端逐格对齐，含跨零点的 `start > end`。

1.4.2 补的一条值得单说：**`admin.js` 读的每个 `BOOT.x` 都必须在视图的 `$boot` 里出现。**
`adminPageData()` 把值备好、视图忘了转发，是这套引导数据特有的一类静默故障 —— JS 侧一律
写成 `Array.isArray(x) ? x : []` 的安全兜底，读到 `undefined` 时功能不是报错而是变成空操作，
页面全绿、契约也不响。同一轮还补了不带 `acs-` 前缀的状态类扫描（`is-*` / `has-*`，之前那轮
只认 `^acs-`，`has-error` 就是这么在询盘表单里挂了很久却没有任何样式的），以及「圈 Tab 与
`aria-modal` 必须成对」和「自动弹出不得抢焦点」。
